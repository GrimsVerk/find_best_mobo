# Transcript coverage is reported, and zero coverage refuses — Plan

Implements **OD-23** (`docs/DESIGN.oracle.md`), which adds **R1012** from the
evidence in **BL-27**: `select` ran twelve minutes before `fetch` finished
writing `data/transcripts/`, wrote 285 selections each carrying no mentions at
all, and printed nothing unusual; `estimate` then printed a zero-character,
zero-token projection closing with R7's "The pipeline STOPS here". Neither
stage says how much of the cache it actually read, so a run that read no speech
is indistinguishable at the console from a finished one.

## Summary

Count how many of the videos a stage considered had a cached transcript, carry
that count in the artifact `select` already writes, print it at both stages, and
refuse when it is zero over a non-empty population.

- **Coverage is recorded per selection, not recomputed per stage.**
  `Selection` gains `has_transcript: bool`, set where `select_all` already
  distinguishes a cache hit from the empty stand-in transcript it substitutes
  today. R1012 asks the projection to print "the same coverage figure", and two
  stages independently re-deriving a number can disagree; one datum written once
  cannot. It also makes the fact durable in `data/selected.jsonl` rather than
  living only in a console line.
- **`data/selected.jsonl` gains one key.** Additive, and no migration is
  written: `data/` is gitignored, regenerated by the stage that owns it, and
  R23's byte-identical guarantee is about reruns of the same code, not about
  reading older files. An existing file without the key is re-made by re-running
  `select`, which is the same command the operator would run anyway.
- **The refusal is exact and narrow.** Zero coverage over a NON-EMPTY population
  refuses, names `fetch`, and exits 1. A partial cache is never an error — the
  per-video tolerance R24's failure ledger owns is untouched — and an empty
  population is a real (zero) result reported as one, exactly as R1005 draws the
  same line between absence and emptiness.
- **The count prints on every run**, not only when something is wrong, because a
  figure that appears only on failure is a figure nobody can compare across runs
  — which is why BL-27's collapse was invisible.
- **Not done here:** nothing about WHY a transcript is missing. That is R24's
  ledger, already built, and this plan neither reads nor changes it.

Two slices, ~300 lines, sequential — slice 2 reads the field slice 1 writes. No
uncertainties: every decision derived from the design, with the three that came
closest to the line worked through below.

## Uncertainties

**No uncertainties — every decision derived from the design.** Nothing here was
guessed, so nothing is filed as a `BL-<n>` and nothing waits on a ruling. Three
questions came close enough to the line that showing the derivation is worth
more than asserting it.

- **Where the coverage datum lives.** Derived from R1012's own wording. It
  requires "every stage that reads the transcript cache" to report coverage AND
  the projection to print "the same coverage figure" — "the same", not "its
  own". Two stages each calling `load_cached` and counting for themselves would
  satisfy the first clause and quietly break the second the moment their
  populations diverge, which they already do: `select` considers every pending
  video and `estimate` considers only the included selections. One field on
  `Selection`, written once and read twice, is the only shape in which the two
  printed numbers are provably the same measurement.
- **Whether the refusal belongs in the command or in the library.** Derived from
  how the two stages are already split: `select.py` and `estimate.py` are pure
  over what they are handed, and `commands/` owns exit codes and console output
  — `commands/select.py` already returns 1 with a message naming the producing
  command when the index is absent. The refusal is the same kind of decision, so
  it lands in the same place, and the library gains only the counting.
- **What "non-empty population" counts.** Derived from R1005's distinction
  between absence and emptiness, applied to the population rather than the file:
  at `select` it is the pending videos the index yielded, at `estimate` the
  included selections. Zero of either is a real corpus fact that must report as
  itself — a channel with nothing in range is not a broken run — so the refusal
  is conditioned on the population being non-empty and never on the count alone.

## The work, sliced

Two slices, and deliberately not three: the change is one recorded fact plus the
two stages that report it. **They are sequential.** Slice 2 reads the field
slice 1 writes and the projection cannot carry a figure that does not exist yet,
so it is built after slice 1 has landed, not beside it.

## Slice 1 — `select` says how much of the cache it read

- **Delivers:** `uv run find-best-mobo select` prints a coverage line on every run — "189 of 285 pending videos had a cached transcript" — and `data/selected.jsonl` records `has_transcript` per video. When the pending set is non-empty and NONE of them has a cached transcript, the stage prints a refusal naming `find-best-mobo fetch`, writes nothing, and exits 1. BL-27's measured run is exactly that case. Covers R1012.
- **Files:** `src/find_best_mobo/select.py`, `src/find_best_mobo/commands/select.py`, `tests/test_select.py`
- **Estimate:** ~160 lines

### Signatures

```python
@dataclass(frozen=True)
class Selection:
    video: Video
    reason: str  # "title_hit" | "threshold" | "excluded_below_threshold"
    mentions: tuple[Mention, ...]
    distinct_canonicals: int
    has_transcript: bool


@dataclass(frozen=True)
class Coverage:
    considered: int
    with_transcript: int


def transcript_coverage(selections: Sequence[Selection]) -> Coverage: ...
def render_coverage(coverage: Coverage, noun: str) -> str: ...
```

`Coverage`, `transcript_coverage` and `render_coverage` live in
`src/find_best_mobo/select.py`, beside `Selection`, which is the type the datum
rides on; `estimate` imports them from there in slice 2 rather than defining a
second pair. `select_video`, `threshold_report` and `ThresholdReport` keep the
signatures they have.

### Behaviour the signatures cannot carry

- **`has_transcript` is set where the substitution already happens.**
  `select_all` calls `load_cached` and replaces `None` with an empty
  `Transcript`; the flag is `cached is not None`, decided at that line. Nothing
  else calls `load_cached` in this module and nothing infers the flag from the
  mention count — a cached transcript with no board mentioned is a real result
  and must read as coverage, not as a miss.
- **`select_video` stays pure and takes the flag from its caller.** It receives
  a `Transcript` and cannot tell an empty cached one from the stand-in, so the
  flag is passed in rather than derived inside. This keeps the one place that
  knows the difference the one place that decides it.
- **`render_coverage` takes the noun** because the two stages count different
  populations — "pending videos" here, "selected videos" in slice 2 — and a
  shared renderer that hard-codes one of them would print a false label at the
  other. The rendered shape is `"<n> of <m> <noun> had a cached transcript"`.
- **The refusal is a `commands/` decision.** `commands/select.py` computes the
  coverage before writing anything, and on `considered > 0 and with_transcript
  == 0` prints the refusal and returns 1 without calling `write_selected` — a
  half-written artifact is what let the stale file mislead the next stage in the
  first place. The message names `find-best-mobo fetch` and says the population
  it measured, in the shape `_missing` already uses for the index.
- **Zero pending videos is not a refusal.** `considered == 0` prints the
  coverage line as `0 of 0` and returns 0. This is R1005's line between an
  absent input and an empty one, and it is the case a channel with nothing in
  the date range legitimately produces.
- **`write_selected` and `read_selected` round-trip the new key.** Records still
  sort by upload date then video id with keys sorted within each record, so
  R23's byte-identical rerun holds with one more key present.

## Slice 2 — The projection cannot be read without its coverage

- **Delivers:** `uv run find-best-mobo estimate` prints the coverage of the selections it is about to excerpt directly beside the `characters of excerpt text` line, so no projection can be read without seeing what fraction of the corpus produced it. When the included selections are non-empty and none has a transcript, it refuses naming `find-best-mobo fetch` and exits 1 instead of printing a zero-token projection under R7's stop sentence. BL-27's measured console output becomes impossible. Covers R1012.
- **Files:** `src/find_best_mobo/estimate.py`, `src/find_best_mobo/commands/estimate.py`, `tests/test_estimate.py`, `docs/architecture.md`
- **Estimate:** ~140 lines

### Signatures

```python
@dataclass(frozen=True)
class Projection:
    coverage: Coverage
```

The existing `Projection` fields are unchanged and `coverage` is added to them;
`project` and `render_projection` keep their signatures, `project` taking the
selections it already receives and reading the flag off them. `Coverage` is
imported from `src/find_best_mobo/select.py` — it is not redefined here.

### Behaviour the signatures cannot carry

- **`project` reads `has_transcript`, it does not call `load_cached`.** The
  field is on the selections `project` is already handed. Re-deriving it here
  would reintroduce the two-measurements problem the Uncertainties section
  rules out, and it would make a pure function touch the filesystem.
- **The population is the INCLUDED selections**, matching the line it sits
  beside: `characters of excerpt text` is summed over the videos that were
  excerpted, and a coverage figure over a different set than the number it
  annotates is worse than none. Rendered with the noun `"selected videos"`.
- **The refusal fires before any bundle is written.**
  `commands/estimate.py` checks the coverage of `_included_recent_first(...)`
  before cutting a single window, so a refused run leaves `data/bundles/`
  exactly as it found it. It returns 1 and names `find-best-mobo fetch`.
- **R7's stop sentence is never printed on a refusal.** The refusal replaces the
  projection block entirely rather than appearing above it; the whole finding of
  BL-27 is that a warning next to the checkpoint's success language annotates it
  instead of separating it.
- **`docs/architecture.md` gains the coverage rule** beside the existing entry
  that records a missing transcript as tolerated. That entry stays true per
  video and is now qualified at the population, so the next agent reading it
  does not restore the silence.
- **The distinguishing pair R1012 asks for is pinned end to end**, through the
  real `read_selected` → `project` → `render_projection` path on a tmp data
  directory, with no network: selections that all have transcripts and
  genuinely zero mentions still produce a real zero projection and exit 0; the
  same selections with no cached transcripts refuse and exit 1. The second is
  the assertion that would have been red on BL-27's run.

## Out of scope

- **Why a transcript is missing.** R24's failure ledger already records the
  class and the error per video, and nothing here reads or changes it.
- **Fetching anything.** No stage gains a network call, implicit or otherwise;
  the refusal names the command the operator runs, and stops.
- **A coverage floor.** Refusing below some non-zero fraction is a different and
  much larger judgement — it would put a number on how much of the corpus a
  projection may be missing — and R1012 does not ask for one.
- **`index` and `fetch`.** Neither reads the transcript cache: `fetch` writes it,
  and its own ledger and halt triggers (R24) already report what it could not
  get.
